# #178 分页试用分支真机复测

2026-11-18 的四份诊断均为 Android Release、约 120 Hz、分页模式、关闭自定义图片处理。用户报告试用分支手动和音量连续翻页观感均正常。本轮主要剩余差距是音量连翻的 UI 耗时长尾。

本地 Next 试用分支 `codex/reader-precache-selection-test` 对应 `cc52be63856a9d62a215aa84c8364c5813b05720`，实现为翻页意图时登记目标、帧后提交预加载窗口。两份 Next 日志的应用版本均为 `1.18.4-rc.1+250`，版本字段无法独立确认安装包 SHA。两份 Prime 日志均为 `2.7.2`，其中 `legacy.referenceCommit` 自报 `ba790fe168ce7ab4c2cba76ef380fda7bbbdd4b7`。这四份导出没有引擎 SHA、可复放输入记录、温度或 CPU、PSS、RSS 采样。不同模式和版本的会话时长、起始缓存驻留和读图次数也不同。

Prime 使用相邻帧的 `vsyncStartUs`，包含静止与阶段边界。Next 的阶段汇总只计算同一 drag 或 settle 内的相邻帧。两份 Next 的帧缓冲均报告零淘汰，导出只含摘要和超预算帧。连翻样本淘汰了 104 个滚动阶段，保留窗口从 3.310 秒开始，settle 汇总覆盖 497 帧中的 159 帧。图片与导航事件缓冲另淘汰 487 条，复制时再省略 207 条，剩余事件从 4.325 秒开始。两版典型产帧间隔约为一个刷新周期，全程运动区间的 P99 或最大间隔需要同口径数据。

Next 连翻保留下来的 14 次请求连续向前，各差一页。请求间隔中位数为 100.816 ms，这是每次开始动画之间的间隔。13 次在请求后 48.156–52.370 ms 由后续输入正位跳到相同目标，随后原动画 Future 结束。最后一次无中途跳转，约 209.447 ms 正常完成。排除小于 5 ms 的瞬时阶段后，保留窗口的 settle 和 idle 中位数为 49.741 和 51.554 ms。这与源码的 200 ms 动画、活动动画被下一次请求以跳页结束相符。 `animationCompleted` 记录 Future 结束，可能发生在跳页中断之后。 [Flutter animateTo](https://api.flutter.dev/flutter/widgets/ScrollController/animateTo.html)

## 仍能定位的 UI 慢帧

使用同一采集相对时钟的 build 起止和导航事件对齐。批量回调的 `receivedAtUs` 仅表示日志何时拿到数据。

| Next 连翻 VSync 起点 | UI | 同窗证据 |
| --- | ---: | --- |
| 2.600 s、2.909 s | 10.592、8.681 ms | 发生在保留阶段和事件之前，缺少页面上下文 |
| 5.440 s | 9.303 ms | build 开始前 2.774 ms 已正位跳页，帧被归到 idle。该帧对应的窗口提交在 build 结束后约 1.179 ms 进入 |
| 5.766 s | 10.422 ms | build 开始后 0.205 ms 选页，位置约越过半页。窗口提交在 build 结束后约 1.044 ms 进入，随后一对 VSync 间隔 16.704 ms |

两帧可以定位到选页和跳页后的 UI 工作，且同轮的预加载窗口提交已在各自 build 计时边界之后。现有数据支持优先对齐选页回调、活动页 PhotoView 与布局、窄范围外壳更新，仍缺少帧内 CPU 调用栈。Prime 的计数器在连翻样本中只记录到 1 次 Reader 和 1 次 Gallery build，Next 没有同位置计数，无法据此比较两版重建次数。以匹配输入的 Profile 定位耗时，再以 Release 核对动画、跳页后的首帧和正位停留，才可判断能否进一步降低这条长尾。

## 图片首显与试用结论

两份 Next 均是本地读取，源读取为 0，缓存预算为 192 MiB，压力事件为 0。手动和连翻的 `displayWait` P95 为 0.028 / 0.040 ms。连翻的首次解码和预加载总等待中位数为 66.142 / 72.241 ms。保留的 28 次连翻缓存查询均为 keep-alive、零 pending。14 张可按图像编号配对的图像在第一条保留缓存查询前已完成解码，提前量为 86.036–110.361 ms，中位数 98.873 ms。这个量是解码完成到查询的间隔。预加载异步等待与实际显示消费者等待应分别看待。

记录试用版的手动帧耗时、连翻已观测的活跃节奏和首显均符合本轮使用体验。连翻 UI 长尾继续单独追踪。资源开销与全程掉帧的验收仍需要同设置的 CPU、内存和呈现数据。
