# 关键词屏蔽原因新增详情入口的导航回归记录

更新时间：2026-11-13。适用分支：`codex/agent-center-tab`。原反馈编号为 U11，现已撤出[上游反馈清单](../feedback/README.md)。本文是分支维护与交接记录，不是可发送的上游 Issue 稿。

## 用户确认的范围与尚未确定的责任

用户明确这是 agent 分支新增“关键词屏蔽原因中点击封面进入漫画详情”功能后出现的问题。原版没有这一新增入口，没有确认原版已有入口存在相同问题。

目前不能确定是上游详情动作的假设不适用于新入口、新功能的路由选择不当，还是两者适配不完整。此前把它列为通用上游缺陷，证据不足，该归类已撤回。也不能因此断言所有责任都在新增功能代码。

- 不向上游单独发布原 U11 Bug Issue，不作为独立上游缺陷纳入后续集中 PR。
- [E04](../feedback/E04-keyword-reason-cover-preview.md) 仍是新增封面预览和详情入口的功能建议。若未来向上游实现 E04，应将正确导航和返回链纳入该功能的实现与回归。
- 如果以后在未增加该功能的上游版本中发现已有入口也存在类似问题，应另行保存真实入口、版本及证据后重新评估；仅人工把详情放进双导航器夹具，不能证明原版用户入口已有缺陷。

## 现象、影响与预期（按用户口吻保留）

我在 agent 分支里打开关键词屏蔽原因，点新增的封面进入漫画详情。点击详情里的标签看起来没有反应；退出详情后，才发现刚才触发的搜索页错误地出现在下层页面。正常从其他入口进入详情时，点击标签应立即打开相应搜索。作者搜索也应遵循同样的导航行为。

这让我无法从当前详情顺畅查看同标签或同作者的漫画，可能误以为没有点中而重复点击；返回时也会看到意外打开的搜索页，打断继续查看屏蔽原因的操作。

我希望点击标签或作者后立即进入对应搜索，返回时依次回到详情和原因列表；搜索结果或推荐漫画的封面继续在当前导航链中打开。

复现步骤：

1. 使用新增原因封面详情入口、尚未修复此问题的 agent 分支构建。
2. 打开关键词屏蔽原因窗口，点击其中的封面进入漫画详情。
3. 点击详情里的标签，观察当前详情是否进入搜索；对作者搜索做同类回归。
4. 退出详情，检查搜索是否错误地出现在下层页面。

## 已有排查、修复与验证入口

分支排查发现：新增原因入口把详情打开在根导航器，原标签动作却选择全局主导航器，使搜索进入详情下层。此机制解释了该新增入口下的症状，不足以判断原版的导航设计是否错误，也没有排除由新入口承担适配的方案。

分支已在 `0788c89380d8960db6647fe9b9acfb18609ddaf8` 中将标签/作者动作改为使用当前详情上下文，并让普通卡片沿所在页面导航，保留搜索参数、后续封面跳转及返回顺序。这是目前分支的修复方案，不代表对责任归属的最终结论。
