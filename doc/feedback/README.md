# 上游反馈稿与后续 PR 入口

整理日期：2026-11-13。目标仓库：[CyrilPeng/Venera-Next](https://github.com/CyrilPeng/Venera-Next)，源码复核基线 `482810df369d126e4011be31d64408e33aede76f`。本目录有 **11 份缺陷/组件问题稿、6 份功能建议稿**，另有本索引及交接文档；没有创建外部 Issue 或 PR。

17 份公开稿件均按“我向上游反馈”的第一人称编写，字段名称与顺序遵循对应上游 YAML 模板，不增加自定义小节。缺陷的**问题说明、可见现象与影响全部写在“实际行为 / Actual behavior”**；建议的场景与不便写在“需求场景 / Use case”。源码与最小验证折叠放进模板已有字段：缺陷用“替代证据”，建议用“建议方案”。维护记录和待办不混进公开正文。

- 设备型号统一占位符：`【设备型号】`。可在各稿中直接替换，已知的 Android 15、骁龙 7gen2+、12 GB 内存保持不变。
- 用户最新确认：清单内保留的缺陷都存在于最新原版 **1.18.4-rc.1**。公开稿统一使用这一版本，不写“二次开发版本发现”“尚未原版复测”或未知二次开发构建号。
- U05a、U05b、U08 属于阅读性能表单，真实诊断尚未提供，诊断方式、报告及无法取得的原因也使用待替换占位符；应填真实情况，不把代理的云环境条件写成你的取日志障碍。
- 原版现象的用户确认与具体根因的验证分开记录：尤其 U01 的“键盘动画每次更新都重建整个页面”仍是怀疑，不写成已有逐帧追踪结果；组件计数不当作手机帧率。
- 界面缺陷的诊断方式与“无法取得日志的原因”均为选填。没有日志、也未确认存在采集障碍时，稿件省略这两个未选择的可选字段，不替用户编造原因；其余已填写字段保持模板顺序。

每份稿件第一行可作为 Issue 标题，正文按对应 YAML 表单同名字段填写。GitHub 已关闭 blank issue，网页需要选择稿件所链接的表单，不能把整份 Markdown 直接塞进单一“复现步骤”字段。未来若用户授权通过 API/CLI 发布，可用标题加正文创建；本轮只写文件。

- **原候选 2/4** 指旧文档待原版确认表中的用户编号 2（U06 收藏详情过场）、4（U07 阅读首帧透明），不是 U02/U04。用户已在原版 **1.18.4-rc.1、Android 15、骁龙 7gen2+、12 GB 内存** 验证，两稿已写入；设备型号已使用 `【设备型号】`，提交前直接替换。
- U01–U05 的旧证据保留；U05 按独立路径拆为 U05a/U05b。U08–U10 为本轮新增阅读问题。
- U01 已补齐用户在原版确认的三个可见场景：进入大收藏夹、从其漫画详情返回、打开收藏夹内搜索时输入法弹出动画严重卡顿；不能只写逐本查历史的实现问题。
- **原 U11 已撤出上游 Issue 和独立缺陷修复范围**：用户明确这是 agent 分支新增“关键词屏蔽原因→封面→漫画详情”入口后出现的问题，尚不能确定责任在上游代码、新功能代码还是两者适配。原稿已移为[分支回归记录](../agent/keyword-reason-detail-navigation.md)，不再作为可发送的上游 Issue。E04 仍是新增入口的功能建议，其实现必须保证详情内导航正确。
- 各稿保留源码、最小组件与原设备的证据范围。性能稿暂未附手机手动阅读诊断，已有线索不会当作设备诊断或截图；发布时如上游要求补充，可按实际情况追加。
- 2026-11-13 检索相关主题并读取 #93/#112/#115/#118/#125/#129：前五项 closed，#129 open / awaiting-feedback；#125 仍有 investigating 标签。发布前仅核对增量讨论，不把旧关闭状态当作新缺陷已解决的证明。
- 后续开发按用户要求：**从上游另建一个工作分支，全部拟提交项集中一个 PR；Issue 则逐项独立**。详见 [PR 交接](upstream-pr-handoff.md)，不从 Agent 整分支提 PR、不整包 cherry-pick。
